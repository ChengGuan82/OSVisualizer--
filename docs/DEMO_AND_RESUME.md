# 演示与简历材料

## 三分钟演示

1. CPU 页加载示例，先运行 FCFS，再切换 RR（时间片 2），观察同一进程多次执行，说明为什么等待时间不能只用首次开始时间计算。
2. 打开“全策略对比”，解释公平性、平均等待与饥饿风险的取舍。把某进程到达时间改为 30，观察空闲段和 CPU 利用率变化。
3. 页面页选择 CLOCK，生成默认轨迹并自动播放；暂停后回退一步，解释固定页框、访问位清零与指针前移。
4. 页框为 3、序列改为 `1 2 3 4 1 2 5 1 2 3 4 5`，FIFO 缺页 9 次；页框为 4 时变为 10 次，展示 Belady 异常。强调物理块增多不保证 FIFO 更好。
5. 导出 CSV，展示算法测试和 `docs/MIGRATION.md`，说明从课程实验到可复现工程的改造。

- 基于操作系统课程实验重构桌面算法可视化平台，将纯 C++ 算法核心与 Qt 展示分离，通过统一策略接口实现 5 种 CPU 调度与 4 种页面置换算法。

## 面试要能回答的设计问题

- 为什么使用结果快照？算法一次性计算后，UI 的暂停与回退只是索引变化；避免回退时重新构造内部状态，代价是存储完整轨迹。
- 为什么算法层不用 Qt？核心可以在无图形环境中测试，也能复用到其他前端。Qt 仅负责用户交互与绘图。
- RR 时间片到达边界怎样定义？本项目先加入新到达进程，再把当前进程重新入队，规则明确且有固定算例。
- 物理页框和淘汰队列有什么区别？物理槽位稳定，队列描述选择淘汰对象的顺序，不能直接把后者当成内存布局。
- SRTF 为什么不用逐单位时间循环？只在进程到达或完成时重选；没有新进程到达时，当前最短剩余进程继续运行。
- 有什么尚可改进？CPU 轨迹目前为等宽片段；可增加比例时间轴、抽离各模块 Controller、资源上限和大轨迹性能基准，再扩展银行家与磁盘调度。

## 测试证据的含义

`core_tests` 中标准算例有确定预期值；随机测试固定种子 408，重复 200 组输入，检查守恒关系、统计公式、独立 FIFO/LRU 参考实现和 OPT 下界。大量断言不等于大量独立测试用例，不应在简历中把断言数包装成测试用例数。

`gui_smoke` 在 Qt offscreen 平台中验证所有策略可运行、输入失效清理、播放/前进/回退/拖动与非法输入。它不替代真实桌面点击体验和跨平台测试。
