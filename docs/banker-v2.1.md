# 银行家算法可视化 2.1

每个进程使用独立卡片，大号显示剩余需求，小号显示持有量和最大需求。点击编辑修改初始资源参数。

## 观察流程

点击自动执行，或使用前后单步、进度条观察四个阶段：

1. 选中一个未完成进程。
2. 逐资源比较剩余需求与可用量，显示满足或具体缺口。
3. 满足条件时借出 Need，进程持有量达到 Max，资源池暂时减少。
4. 模拟完成后归还 Allocation + Need，资源池相对检查前净增加原 Allocation，进程进入安全序列轨道。

若资源不足，第 3、4 阶段保持资源池不变并提示跳过。资源流动通道中的标记以 R0 × 数量表示转移量；转移量为 0 时不生成标记。

资源柱使用统一刻度和共同基线，浅色为总量，亮色为当前阶段的模拟可用量。柱和数字显示所选阶段的确定状态，移动标记解释该阶段发生的转移。每次转移动画持续 650 毫秒，自动回放每 800 毫秒推进一个阶段。前后跳转会取消旧转移动画并重建当前阶段。

总量 = 初始可用量 + 所有进程初始持有量，模拟中保持不变。数量跨度极大时，极小总量柱使用最小像素高度，精确值以标签为准。

安全序列按完成顺序填入，演示结束才揭示安全或不安全结论。若无法继续，每个未完成进程显示具体缺口。序列是算法找到的一条可行序列，不代表唯一答案。本版不包含练习模式。

修改参数将清除回放和旧结论。无效参数会提示错误；完成卡片显示当前持有量和剩余需求为 0，编辑窗口仍使用初始参数。

这是安全性检查的模拟，不是实际分配。不安全不等于已经死锁。

运行 Release/v2.1/OSVisualizer.exe，进入银行家算法页面。

## 验证

自动检查覆盖阶段扣减与归还、序列延迟揭示、倒退还原、共同刻度、最终安全结论、不安全缺口、零需求、非法参数和维度变更。另运行已有算法与界面回归测试。
